# Learning path

Work through the stages in order, building something at every stage.

1. **Ruby fundamentals** — objects, methods, collections, errors, and tests.
2. **Web foundations** — HTTP, DNS, cookies, JSON, and the request lifecycle.
3. **SQL and PostgreSQL** — tables, indexes, constraints, transactions, and
   query plans.
4. **Rails fundamentals** — routing, controllers, models, validation, and
   serialization.
5. **Application boundaries** — authentication, authorization, APIs, and
   service boundaries.
6. **Asynchronous work** — queues, retries, idempotency, and scheduled jobs.
7. **Production engineering** — caching, deployment, logging, metrics, and
   incident response.
8. **Scale and distributed systems** — consistency, rate limiting, and failure
   isolation.
9. **Algorithms** — complexity, data structures, pagination, and scheduling
   patterns used by backend systems.

Use the [project sequence](projects.md) to turn each stage into practice.

!!! tip
    Do not skip testing and database fundamentals. Most Rails production bugs
    are boundary bugs, not syntax bugs.
